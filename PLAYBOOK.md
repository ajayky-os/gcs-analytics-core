## Build & test facts
- Build tool / wrapper: `./mvnw` (never bare `mvn`). **Requires `JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64`** — Maven 3.9.16 fails with `ClassNotFoundException: MavenCli` under the corp default JDK 26 (`/usr/local/buildtools/java/jdk`). `loop.yaml` exports this for every gate; do the same in any ad-hoc shell.
- `GPKG_NOINFO=1` silences the corp-airlock banner that otherwise pollutes logs; `MAVEN_SKIP_RC=1` bypasses `/etc/mavenrc` when a newly merged Renovate dependency bump on `origin/main` (e.g. `libraries-bom`) is still inside the Corp Airlock soaking window.
- **Timeout Option Validation & `Duration.compareTo` Guard**: When validating `Duration` options against an integer-millisecond upper bound (`MAX_HTTP_TIMEOUT = Duration.ofMillis(Integer.MAX_VALUE)`), always evaluate `timeout.compareTo(MAX_HTTP_TIMEOUT) <= 0` rather than `timeout.toMillis() <= Integer.MAX_VALUE`. Calling `toMillis()` on large durations like `Duration.ofSeconds(Long.MAX_VALUE)` throws raw `ArithmeticException: long overflow`, crashing callers unexpectedly instead of triggering clean `IllegalArgumentException` fail-fast validation. Furthermore, validating `<prefix><key>` at configuration time in `GcsAuthOptions` ensures error diagnostics retain the prefixed property name rather than failing lazily inside `GcsHttpTransportFactory.toTimeoutMillis` with generic parameter names.
- **Telemetry Option Normalization & JaCoCo Branch Preservation**: In `LoggingTelemetryOptions` and `OpenTelemetryOptions`, normalize parsing via `ConfigurationUtil.getTrimmedValue(analyticsCoreOptions, key)` and `Locale.ROOT` + `.replace('-', '_')`. Keep `project-id` excluded from the presence gate (it is a shared prefix-level key). Crucially, use explicit `if (opt.isPresent())` blocks rather than chained `.ifPresent(...)` or `.map(...).ifPresent(...)` lambdas when replacing legacy `if (val != null)` blocks: polymorphic lambda dispatch eliminates bytecode `IFNULL`/`IFNONNULL` jump instructions, reducing total covered branches in classes with 100% coverage and mechanically dropping the aggregate repository branch coverage percentage below the `-0.10%` non-regression threshold.
- **Customer-Supplied Encryption Keys (CSEK) in Tests**: Customer-supplied encryption keys (CSEK) in Google Cloud Storage must be 256-bit (32-byte) AES keys. Test constants for encryption/decryption keys must always be valid Base64-encoded 32-byte keys (e.g. `"MDEyMzQ1Njc4OTAxMjM0NTY3ODkwMTIzNDU2Nzg5MDE="`, decoding to 32 ASCII bytes `"01234567890123456789012345678901"`, 99 chars within the 100-col limit) rather than arbitrary short strings, maintaining parity with `GcsClientImplTest.TEST_ENCRYPTION_KEY` and preventing failures if SDK/client-side key-length validation is enforced.
- **PR Review Comments**: Never blindly resolve any review comment thread (human or `gemini-code-assist[bot]`). Every unresolved inline comment must be evaluated and answered on its thread via `sil.py pr-push --replies-json` with either **(a)** what code change was made in the amended commit, or **(b)** the concrete technical rationale for why the suggestion is not considered.
- **Enum Option Normalization in `createFromOptions` (`ConfigurationUtil.getTrimmedValue`)**: In configuration parsing, always read optional enum properties using `ConfigurationUtil.getTrimmedValue(analyticsCoreOptions, key)` before mapping with `.map(s -> EnumType.valueOf(s.replace('-', '_').toUpperCase(Locale.ROOT)))`. `ConfigurationUtil.getTrimmedValue` treats blank/whitespace-only values as absent, gracefully falling back to defaults (matching XML/Hadoop conventions where empty `<value></value>` tags represent unset properties), while preserving fail-fast `IllegalArgumentException` on invalid non-blank values. Mapping with `Locale.ROOT` prevents Turkic locale (`tr-TR`, `az-AZ`) casing bugs on `'i'`-bearing enum constants (such as `PARALLEL_COMPOSITE_UPLOAD` or `JOURNALING`). Test blank string handling with `createFromOptions_withBlank<Option>_retainsDefault` asserting the default enum constant.
- **Cache & Numeric Option Normalization via `ConfigurationUtil.getTrimmedValue`**: Parse optional cache/boolean/numeric properties using `ConfigurationUtil.getTrimmedValue(options, key).map(Boolean::parseBoolean | Long::parseLong)`. Raw `Boolean.parseBoolean` without trimming silently evaluates `" true "` to `false`, accidentally disabling features like caches, while raw `Long.parseLong` on whitespace-padded numbers or empty XML `<value></value>` tags throws `NumberFormatException`. Using `getTrimmedValue` treats blank/empty and `null` values as absent (retaining default capacities/flags) and trims surrounding whitespace before parsing.
- **Write Option Normalization via `ConfigurationUtil.getTrimmedValue` & Non-Vacuous Boolean Tests**: Parse write options (booleans, KMS key, user-project, CSEK) via `ConfigurationUtil.getTrimmedValue(options, key)`. For options that default to `true` (`overwriteExisting`, `disableGzipContent`), raw `Boolean.parseBoolean("")` or `" true "` silently inverts the default to `false` (injecting `BlobWriteOption.doesNotExist()` and causing spurious 412 write failures), while empty strings for KMS/user-project/CSEK trigger opaque wire HTTP 400s. In unit tests, asserting padded `" false "` is vacuous because `Boolean.parseBoolean(" false ")` evaluates to `false` without trimming; non-vacuous boolean trim verification must test `" true "` across both default-`true` and default-`false` properties.
- **Truth Assertions on `Optional<byte[]>` (`OptionalSubject.hasValue`)**: Google Truth's `assertThat(Optional<T>).hasValue(expected)` unwraps `actual.get()` and delegates to `Subject.isEqualTo(expected)`, which executes `Subject.checkByteArrayEquals` (`Arrays.equals`) when both operands are `byte[]`. It does *not* invoke `Optional.equals` (which only checks reference equality on arrays). Never unpack `Optional<byte[]>` via `.orElse(null)` solely to assert array equality; doing so degrades Truth's `but was empty` failure diagnostics to `but was: null` and risks NPE if the `Optional` reference itself is unexpectedly null.
- **Verification of Channel Invocations & Counters in Unit Tests**: Whenever a tracking variable such as `AtomicInteger dataReadCount` or `AtomicBoolean readAttempted` is declared as a named local variable in `Arrange`, always assert it in `Assert` (`assertThat(readAttempted.get()).isTrue()` / `assertThat(dataReadCount.get()).isEqualTo(1)`). Leaving it unasserted leaves dead Arrange code and fails to enforce the single-I/O upper bound (`dataReadCount <= 1`). Moreover, when the returned value is a sentinel/pass-through default (`0` or `-1`), asserting the tracking counter prevents vacuous passes from early bail-outs (e.g. `!isLikelyFooterRead` returning 0 without reading, or unstubbed Mockito `source.size()` defaulting to `0L` and returning -1 via `resolveFileSizeExplicitly`). If a test intentionally does not care about invocation count, pass `new AtomicInteger(0)` anonymously inline.
- **Testing `equals`/`hashCode` and Type Equality Contracts**: Single-element Guava `ImmutableSet.of(first)` returns `SingletonImmutableSet`, whose `contains` method delegates solely to `element.equals(target)` without ever invoking `hashCode()`. To test hash-based collection lookup across equivalent distinct instances, use a real hash table (`Set<T> set = new HashSet<>(Set.of(first)); assertThat(set).contains(second);`). When testing inequality against disparate types (`!(o instanceof T)`), asserting against a final literal like `isNotEqualTo("STRING")` triggers Error Prone `[TruthIncompatibleType]`; assert `assertThat(base).isNotEqualTo(new Object());` directly without allocating intermediate collections or suppressing warnings. Note: Only test `equals`/`hashCode` on classes with hand-written equality logic or overrides; never write unit tests solely to cover `@AutoValue` generated equality methods.
- **Byte Size Constants in Tests (`KB`/`MB`) and Non-Throwing Methods**: Always declare `private static final int/long KB = 1024` and `MB = 1024 * KB` at the top of test classes (typed strictly to match method parameters/return types) rather than using raw magic byte numbers (e.g. `8192`, `16777216`, `4 * 1024`, `8 * 1024 * 1024`) or placing constants mid-class. Use `KB` consistently across all byte-size options/sizes (`setSize(KB)`, `setMaxMergeSize(KB)`), but retain plain numeric literals for non-size offsets and seek targets (`position(100L)`, `createRange(/* offset= */ 1024, ...)`). When testing methods that do not throw exceptions (e.g. no-op default interface implementations), invoke them directly rather than wrapping in JUnit's `assertDoesNotThrow(...)` to adhere strictly to Google Java testing style and avoid redundant assertion libraries.
- **`ReadableByteChannel` Blocking Contract & Infinite Spin Prevention**: `ReadableByteChannel` implementations for blocking channels (such as `GcsBidiReadChannel`) must never return `0` on in-bounds reads when `dst.hasRemaining()` is true; returning 0 causes callers like `SmallObjectOptimizer.ensureCached` and `GcsFooterOptimizer.loadFooter` (which loop `while (buffer.hasRemaining()) { if (source.read(buffer) == -1) ... }`) to enter an infinite spin loop. When writing unit tests characterizing current behavior where an empty payload returns 0, never lock in the 0 return as an intended contract without an explicit `// TODO:` comment citing the blocking specification and optimizer spin risk.
- **Accurate Test Naming for Stub/No-Op Methods**: Never imply stateful coupling in test names when asserting unconditional constants on stub implementations. If a dummy/anonymous strategy's `getLimit()` unconditionally returns `0`, asserting `getLimit() == 0` after `position(offset)` does not test that `position` preserved the limit; name such tests honestly (`createReadStrategy_positionAndGetLimit_areNoOps`) to document that both methods are stubs.
- **Diff Hygiene vs. Broad Test Refactoring**: When considering reviewer suggestions to reuse a new helper across dozens of pre-existing tests (e.g., wrapping 20+ tests in `try-with-resources`), always calculate the `git diff --numstat` (`added + deleted`) cost. Because `google-java-format` (Spotless) re-indents every non-blank line in the test body by +2 spaces, wrapping 20+ test bodies generates ~450+ diff lines and causes a deterministic hard-gate failure on `hygiene.max_changed_lines: 400`. Defer broad test-fixture migrations to a dedicated cleanup PR and reply to the reviewer with the concrete diff-budget arithmetic.
- **Redundant Imports and Wildcard Imports in Tests**: `google-java-format`'s `RemoveUnusedImports` in Spotless only removes unused imports whose simple names are not referenced in the AST; it does not remove redundant single-type imports that duplicate a package wildcard (e.g. importing `com.google.cloud.gcs.analyticscore.client.HermeticGcsFileSystem` when `com.google.cloud.gcs.analyticscore.client.*` is already present). Never introduce redundant single-type imports alongside wildcard imports, and strictly annotate parameters with `@Nonnull`/`@NonNull` on touched or added constructor signatures per the styleguide.
- **Avoid Mocking `@AutoValue` Data Carriers in Tests**: Never use `mock(GcsItemInfo.class)` or mock `@AutoValue` data carriers (`GcsItemId`, `GcsItemInfo`, `GcsFileInfo`). Mocking data carriers couples tests to internal getter invocations and leaves unstubbed getters in invalid `null` states. Always instantiate real instances using their builders (`GcsItemInfo.builder().setItemId(...).build()`).
- **Prefer `ApiFutures.immediateFuture` / `ApiFutures.immediateFailedFuture` over Mocking `ApiFuture`**: Never use `mock(ApiFuture.class)` and stub `.get()` for completed or failed future responses. Mocking `ApiFuture` introduces raw type warnings, unneeded Mockito overhead, and fragile over-specification of specific `get(...)` overloads. Always use type-safe `ApiFutures.immediateFuture(...)` or `ApiFutures.immediateFailedFuture(new StorageException(...))` per the repository's "Fakes over Mocks" convention. Reserve mocking `ApiFuture` strictly for cases simulating in-flight blocking interruptions or timeouts (`InterruptedException`/`TimeoutException`).

When condition clauses already describe the failure (e.g. `...ThrowsIOException`), bare `_throws` is idiomatic and avoids redundant identifier length.

- **Positional reads (`readFully`/`readTail`)**: per-call temporary channels never accumulate adaptive seek history; opening them with `FileAccessPattern.RANDOM` (precedent: `GcsReadChannel.readVectored`) avoids `skipInPlace` byte discards and unbounded chunked reads on fresh sequential channels, cutting `HermeticInputStreamBenchmark.positionedReads{objectSize=1048576}` bytes served by `-41.4%` (1.54 MB -> 901 KB) and latency by `-14.6%` (PR #439).
