- `GcsReadChannelOpenBenchmark` showed `openAndReadOneByte_withItemId` was **3.3× slower** (`2.96 µs/op`, `9,432 B/op`) than `openAndReadOneByte_withFileInfo` (`1.18 µs/op`, `3,048 B/op`) because `GcsReadChannelMetadataExtractor` walked the class hierarchy and cloned `Method[]` per open; fixed in `20261027-095436-cache-metadata-extractor-reflection` (PR #421) via `ClassValue` caching (`0.89 µs/op`, `-70.1%` latency; `2,516 B/op`, `-73.3%` alloc).
- `AbstractReadStrategy.skipInPlace` previously allocated a `128 KiB` `skipBuffer` per strategy instance on forward seeks within `inplaceSeekLimit` (`140.5 KiB/op` in `ReadStrategyBenchmark.seekAndRead(forwardGapBytes=4096|65536)`); fixed in `20261027-140432-reuse-threadlocal-skip-buffer` (PR #422, merged into `origin/main` at `6d0749e67e`) via `ThreadLocal<SoftReference<ByteBuffer>>` (`9.4 KiB/op`, `-93.3%` alloc; `-63.2%` to `-73.3%` latency across all 6 forward-gap cases, and `-51.9%` alloc / `-36.3%` latency on `HermeticInputStreamBenchmark.positionedReads{objectSize=1048576}`).
- `VectoredIoUtil.mergeGcsObjectRanges` previously called `currentCombinedRange.union(nextRange)` inside its merge loop, creating a new `ImmutableList.Builder` and copying all previously merged `GcsObjectRange` elements on every step (`O(N^2)` time/allocation: `2.71 ms/op` and `39.7 MB/op` at `ranges=4096, gapBytes=0`), and sorted via `ranges.stream().sorted(...).collect(toImmutableList())` (double array copy). Fixed in `20261028-071714-linear-vectored-range-merge` (PR #426) using `ImmutableList.sortedCopyOf(OFFSET_COMPARATOR, ranges)`, primitive `currentOffset`/`currentEnd`, and a lazy `ImmutableList.Builder<GcsObjectRange>` allocated only when at least 2 ranges coalesce: improved all 9 `VectoredRangeCoalescingBenchmark` cases, up to **`-99.0%` latency (`2.71 ms -> 27.2 µs/op`, 100× faster)** and **`-99.8%` allocation (`39.7 MB -> 92.2 KiB/op`, 430× less memory)** at `ranges=4096`, and `-21%` to `-44%` on unmerged `gapBytes=1048576` cases.
- Cloudtop cron timing: `refresh_queue.sh` runs at `:00` and `:30` UTC (`0,30 3-13 * * 1-5`); start `sil.py baseline` and `sil.py gates` in the quiet windows (`:02`–`:22` or `:32`–`:52` UTC) and never run `sil-coder` Maven builds concurrently with `sil.py baseline`.
- When caching reflective `Method`s via `Class.getMethods()`, wrap `method.setAccessible(true)` in `try ... catch (RuntimeException)` because JDK 9+ throws `InaccessibleObjectException` for methods on non-public classes in closed modules; `Files.readAttributes(FileSystems.getFileSystem(URI.create("jrt:/")).getPath("/"), BasicFileAttributes.class)` (`jdk.internal.jrtfs.JrtFileAttributes.size()`) deterministically exercises this in unit tests across all OSes.
- In JMH benchmarks of callback APIs (`OperationListener`), empty callback bodies allow C2 to inline and scalar-replace the argument objects (`MetricKey`, `Collections.singletonMap`); consuming `operation.getName().hashCode() ^ metrics.size()` into a `volatile long` sink increased `recordMetric(listenerCount=1)` from `3.0 ns/op` to `11.7 ns/op` (and `listenerCount=8` from `7.6 ns/op` to `41.4 ns/op`). `Telemetry.measure` costs ~1.3 ns/op with 0 listeners vs ~165 ns/op with 1 listener (`Operation.newOperationId` UUID formatting + `ConcurrentHashMap` + `MetricKey` allocation).
- **Positional reads (`readFully`/`readTail`)**: per-call temporary channels never accumulate adaptive seek history; opening them with `FileAccessPattern.RANDOM` (precedent: `GcsReadChannel.readVectored`) avoids `skipInPlace` byte discards and unbounded chunked reads on fresh sequential channels, cutting `HermeticInputStreamBenchmark.positionedReads{objectSize=1048576}` bytes served by `-41.4%` (1.54 MB -> 901 KB) and latency by `-14.6%` (PR #439). Always read from `ReadableByteChannel` in a counter-bounded loop (`readUpTo`) breaking on `read <= 0` because `SmartReadChannel` / optimizers can return partial byte slices before EOF; fail fast with `EOFException` before opening a channel when file size is known and `length > Math.max(0L, size - position)`.
- **`Telemetry.measure` and `MetricKey`**: In `TelemetryOverheadBenchmark.measureOperation`, C2 already scalar-replaces `AutoValue_MetricKey.Builder` on OpenJDK 17. The escaping bare keys account for at most `48 B/op` (`2 × 24 B` in the 392 B total), which is below `alloc_noise_floor_bytes: 64.0` in `.sil/loop.yaml` (forcing `alloc_res = NO_CHANGE` in `jmh.py`), and the ~2–4 ns latency delta falls well within the Welch MDE (~9–11 ns). `recordMetric` uses non-empty `ATTRIBUTES` (0 B saved). Unbounded static caching on the public, unsealed `Metric` interface creates a memory and classloader leak hazard.
- **Targeted Submodule Test Runs**: When running targeted tests with `-Dtest=...` on a submodule (e.g. `./mvnw -pl client test -Dtest=...`), omit `-am` or pass `-Dsurefire.failIfNoSpecifiedTests=false` so surefire does not fail on upstream reactor modules that lack matching test classes. In `GcsWriteChannel.isOpen()`, `!closed && Optional.ofNullable(sdkWriteChannel).map(WritableByteChannel::isOpen).orElse(false)` emits a second conditional jump for the outer `&&` expression on line 88 (`<line nr="88" mi="2" ci="10" mb="1" cb="1"/>`), which requires a positive assertion on `channel.isOpen() == true` on an open channel to cover. In `GcsBidiWriteChannelTest`, overriding `@BeforeEach` stubbing with `when(mockSession.open()).thenReturn(null)` cleanly exercises all `gcsAppendChannel == null` lifecycle branches (`:83`, `:114`, `:129`) without reflection.
- **Testing `close()` vs. Test Fixture Channels**: Use `try-with-resources` whenever an `AutoCloseable` channel/stream is a fixture for another operation (`write_*`, `isOpen_*`, read tests). When `close()` itself is the explicit **Act** under test in `close_*` unit tests immediately following construction, invoke `channel.close()` directly on a bare local reference without `try-with-resources`. Wrapping in try-with-resources invokes `close()` twice, breaks the mandatory Arrange-Act-Assert (AAA) structure, and introduces verification ordering anomalies for mock delegates.
- **Enhanced-For Loop Branch Coverage & Natural Exhaustion in JaCoCo**: JaCoCo reports a missed branch (`mb=1, cb=1`) on the `for (Type x : collection)` loop statement itself whenever every test case terminates the loop prematurely via an early `break;`. The `hasNext() == false` loop exit branch is only evaluated when the loop is allowed to run to natural exhaustion without breaking (e.g. by querying an offset or range spanning or after the last element). In ordered layout models (`ParquetRowGroup`, `ParquetFileLayout`), ensure the test suite exercises the full partition: before first element, inside element, in gaps between non-contiguous elements, and at/after final `endOffset`.

## Benchmarks
- **Hermetic benchmarks are merged on `main` (`#407`–`#412`)** under `benchmarks/src/main/java/com/google/cloud/gcs/analyticscore/benchmarks/` (7 suites / 45 cases). `gates.perf` in `.sil/loop.yaml` runs all 45 cases directly from `benchmarks/target/classes` with `-prof gc` and no `SIL_GCS_TEST_BUCKET` requirement, evaluating Class D (`readerOpens/op`, `bytesServed/op`), Class S (`gc.alloc.rate.norm` in `B/op`), and Class P (`primaryMetric` latency).
- **`IoCounters` (`@AuxCounters(Type.EVENTS)`)**: `IoCounters.record(storage)` accumulates (`+=`) per-invocation deltas within each measurement iteration; both `sillib/jmh.py` (`_normalize_io_samples`) and Kokoro's `compare_benchmark` (`extract_io_counters`) normalize `readerOpens` and `bytesServed` per operation using `est_ops = meas_time_s / (lat * unit_sec)` and `(b_raw / o_raw) * o_per_op` (`sd = 0`). PR `#414` wired `IoCounters` into the remaining `HermeticInputStreamBenchmark` methods (`sequentialRead`, `readTailWithFooterPrefetch`).
- First smoke numbers (1 MiB, JDK 17, noisy box): sequentialRead ≈ 260 µs, readVectored ≈ 345 µs, readTail ≈ 63 µs, positionedReads ≈ 3.8–10 ms (64 opens; ~275 KB allocated per open → **perf lead: per-open allocation in the channel/strategy stack**). positionedReads varied 2.7× between short runs — needs the full `-f 2 -wi 3 -i 5` and a measured CV% before use as a gate target.
- Every class in the original `core/src/jmh` (TelemetryBenchmark, SmallObjectCachingBenchmark, ParquetFooterParsingBenchmark, ParquetRecordReadBenchmark, GcsReadChannelBenchmark) calls `IntegrationTestHelper.uploadSampleParquetFilesIfNotExists()` and needs `-Dgcs.integration.test.bucket`; they are Tier-2 (real GCS) benchmarks and should never gate small deltas.
- Benchmarks considered trustworthy (low CV%): _fill after first JMH baseline_.
- Minimum JMH settings for a believable verdict: `-f 2 -wi 3 -i 5` (raise forks for noisy ones).

## Where the opportunities usually are

## Do-not-repeat list
- **`GcsClientOptions.generateSessionConfig` and `UploadType`**: `GcsClientImplTest` already exercises `generateSessionConfig` across all upload types (PCU with all cleanup strategies, write-to-disk with/without temp paths, temp-dir IOException, journaling, and chunk upload); `default:` at line 285 is permanently unreachable (4-value enum).
- **`com.google.cloud.storage.Blob` construction**: `Blob` has a package-private constructor `Blob(Storage, BlobInfo.BuilderImpl)`; fakes in outside packages (like `InMemoryStorage` in `test-lib`) cannot instantiate `Blob` directly without reflection.
- **Do not share `GcsFooterOptimizer` / `SmallObjectOptimizer` instances across concurrent `GoogleCloudStorageInputStream.readFully` calls**: `GcsFooterOptimizer` has 9 non-volatile, unsynchronized mutable fields (`localFooterBuffer`, `localBufferStartPosition`, `fileSize`, `pendingSpeculativeBuffer`, etc.); `adoptFooterBuffer` writes `localFooterBuffer` before `localBufferStartPosition`, creating a publication race where concurrent threads can read corrupted bytes from offset `position + 1`.
- **Do not replace `ByteBuffer.allocate(prefetchSize)` with `footerView.slice()` in `GcsFooterOptimizer.toCanonicalFooter`**: `footerView.slice()` retains a strong reference (`HeapByteBuffer.hb`) to the `2 * estimatedPrefetchSize` (`256 KiB`) speculative backing array inside the global Caffeine `footerCache` while `AnalyticsCacheManager` weighs entries by `value.remaining()` (`128 KiB`), silently doubling retained old-gen heap memory.
- **Do not attempt `cache-bare-metrickey` (caching bare MetricKey instances in Telemetry)**: C2 already scalar-replaces `AutoValue_MetricKey.Builder` on OpenJDK 17. The heap saving is at most 48 B/op (below the 64 B/op noise floor), `recordMetric` uses non-empty attributes (0 B saved), and caching on open interface `Metric` leaks classloaders.
- **Do not precompute `BlobId` in `AbstractReadStrategy.<init>`**: `AbstractReadStrategy.itemId` is `protected volatile` and is mutated mid-stream by `updateItemInfo()` to record `contentGeneration`; precomputing `BlobId` in the constructor drops generation pinning on subsequent reopens. Additionally, `BlobSourceOption` elimination saves only 16–64 B/op (below the 64 B/op noise floor and 5% MDE).
- **Caffeine TTL eviction unit tests**: Never use `Thread.sleep(` (forbidden by hygiene rule in `.sil/loop.yaml` line 101). Use `createWithTtlOnly(1, TimeUnit.NANOSECONDS)` + monotonic spin `while (System.nanoTime() - start < 1_000L) { Thread.onSpinWait(); }` + `cleanUp()` for 100% deterministic eviction assertions.
